# 02_plan.md の問題点と修正案

## 問題点分析

### 1. **依存ファイル確認が後回しになっている**
- **Issue:** Phase 1 で「推奨」として新規クラス作成を示唆しているが、既存コード（Enemy3.cs など）を読んでから決定すべき
- **根拠:** 既存システムの制約が仕様に影響する（例：PlayerCollision の実装方式が盾ロジックの実装手段を決める）

### 2. **Phase 1.2 が実装を阻む（決定不足）**
- **Issue:** 「盾防御範囲」「耐久度」「破壊時の状態変化」などが未決定のまま Phase 2 へ進もうとしている
- **結果:** Phase 2 の実装ステップが不確定な仕様で始まり、手戻りが増える
- **修正:** Phase 1 を「仕様確定フェーズ」として、実装前に全パラメータを決定する

### 3. **実装順序が依存関係を無視している**
- **Issue:** 実装優先度は「基本実装 → テスト → 調整」だが、テストシーン作成には仕様確定が必須
- **現状:** 仕様未決定のまま テストシーン作成へ進む矛盾がある

### 4. **Phase 3 の「ゲーム性検証」が曖昧**
- **Issue:** 「実感を得られるか」「適切か」という主観的評価が完了条件に含まれている
- **問題:** 「完了」の判断基準が不明確で、レビューできない

### 5. **完了条件が中間状態を定義していない**
- **Issue:** "✓ 実装完了" "✓ テスト完了" という最終状態のみ示している
- **問題:** 進捗追跡ができず、Phase 間のゴールが不明確

### 6. **ビジュアルアセット の準備状況が不明**
- **Issue:** 盾のモデル・アニメーションが既存アセットか新規作成かが不明
- **影響:** Phase 2.4（プレハブ作成）で止まる可能性

---

## 修正案

### 修正 1: 依存ファイル確認を Phase 1 の冒頭に移動
```
Phase 1: 設計と既存コード確認

1.0 依存ファイル読み込み（最優先）
  - [ ] EnemyBase.cs を読み、敵システムの基本構造を理解
  - [ ] Enemy3.cs を読み、既存実装パターンを確認
  - [ ] PlayerCollision.cs を読み、弾衝突処理の制約を把握
  - [ ] 判定： 新規クラス作成 vs Enemy3 拡張の決定
```

### 修正 2: Phase 1.2 を「仕様確定」に昇格
```
1.1 盾システムの仕様確定（実装前に全て決定）
  - [ ] 防御範囲： 前方180度 or 全方向 → 決定
  - [ ] 耐久度： X回の攻撃で破壊 → 数値を決定
  - [ ] 破壊時状態： 防御解除後の敵動作 → 仕様記載
  - [ ] ビジュアル： 既存モデル利用 or 新規作成 → 確認
  - [ ] 出力： これらを「盾ロジック設計書」として EnemyShield.cs のコメント頭に記載
```

### 修正 3: 実装順序に中間チェックポイントを追加
```
実装ステップ（見直し版）
1. EnemyShield.cs の骨組み実装 → レビュー待機
2. 盾衝突判定ロジック実装 → ユニットテスト確認
3. 盾耐久度トラッキング実装 → 破壊時処理の動作確認
4. テストシーン作成と単独プレイテスト
```

### 修正 4: Phase 3 の検証条件を具体化
```
3.2 ゲーム性検証（数値ベース）
  - [ ] 盾耐久度 = 3回で破壊 → 確認
  - [ ] プレイヤー弾速度で防御範囲に当たるか → 実測確認
  - [ ] 破壊後、敵が通常ダメージを受ける → ゲームオーバーまでプレイ確認
  - [ ] フィードバック： 盾破壊時に SE や色変化がある → 視聴確認
```

### 修正 5: 完了条件を段階的に定義
```
## 各フェーズの完了条件

### Phase 1 完了：仕様書が固定される
- ✓ EnemyShield.cs のコメントに盾ロジック仕様が記載
- ✓ 防御範囲・耐久度・状態遷移が数値で決定

### Phase 2 完了：プレハブが動作する
- ✓ EnemyShield クラスがコンパイル成功
- ✓ テストシーンで盾敵がインスペクタに表示される
- ✓ Play ボタンで敵が移動する

### Phase 3 完了：ゲーム性が確認される
- ✓ 盾敵 vs プレイヤーで、弾が盾で防がれる動作を確認
- ✓ 盾耐久度 3 回で破壊される
- ✓ 破壊後、敵ダメージが有効になる
- ✓ テストシーンが Assets/Scenes/Test/ に保存されている
```

### 修正 6: 依存ファイル確認を明確に
```
## Phase 0: 前提条件確認（最初にやること）
  - [ ] EnemyBase.cs : 敵の基本構造、ダメージ処理
  - [ ] Enemy3.cs : Enemy3 の現在実装内容
  - [ ] PlayerCollision.cs : 弾の衝突ロジック、ダメージ適用方法
  - [ ] ビジュアルアセット準備状況 : 盾モデルの有無
  
  **出力:** 前提条件確認シート（依存関係マップ）
```

# Phase 3 テスト実行計画（02_plan.md）の具体的問題点

## 【問題 1】前提条件の未検証
**Issue:** "以下が完了済みと仮定" と記載しているが、EnemyShield.cs, TestShield.unity の存在確認がない

**修正案:**
```
Phase 3 実行前にプリチェック実施
- [ ] ls -la Assets/Script/EnemyShield.cs で存在確認
- [ ] ls -la Assets/Scenes/TestShield.unity で存在確認
- [ ] EnemyShield.cs のコンパイル確認（Assets でエラーなし）
- [ ] PlayerCollision.cs に盾判定ロジックが含まれているか grep で確認
```

---

## 【問題 2】テスト結果記録先が不明確
**Issue:** "テスト結果の記録方法" セクションはテンプレート形式だが、実際の保存ファイルが指定されていない

**具体的な問題:**
- テスト中の記録は 03_verify.md なのか、新規ファイルなのか？
- PROCESSING.md への転記タイミングが「テスト完了後」となっているが、途中経過はどこに記録？

**修正案:**
```
【テスト記録の3段階】

1. テスト実行中 → 03_verify.md に詳細記録
   （ステップごとに期待値 vs 実結果を記載）

2. テスト完了 → 02_plan.md を参照しながら完了チェック
   （各ステップの最終判定：✓ OK / ✗ NG / ⚠ 要調整）

3. 成果確定 → PROCESSING.md に最終値を記録
   （決定値：耐久度=3, 防御範囲=180度 など）
```

---

## 【問題 3】複数敵パターン（ステップ 5）の前提が不明確
**Issue:** ステップ 5「複数敵パターンテスト（オプション）」と記載だが、前段階で依存している場合の扱いが曖昧

**具体的な問題:**
- "複数敵シーンがある場合" とあるが、存在しない場合はスキップするのか？
- スキップした場合、Phase 3 は完了と見なすのか？

**修正案:**
```
ステップ 5 を2つに分割：

5A【必須】単独敵テスト（ステップ1～4で完了）
   └─ この時点で Phase 3 実行完了と判定

5B【オプション】複数敵連携テスト（RoomData に複数敵シーンがある場合のみ）
   └─ 別途「Phase 3.5」として後続
```

---

## 【問題 4】テスト中の「修正 → 再テスト」フローが定義されていない
**Issue:** "NG / 要調整が発生した場合" のセクション（数値調整フェーズ）は修正内容を列挙しているが、再テストの実施手順がない

**具体的な問題:**
- コード修正後、どの範囲を再テストするのか？
- 前のステップから全て再実行するのか、該当ステップのみか？

**修正案:**
```
【修正 → 再テスト フロー】

NG / 要調整 が検出される
  ↓
修正該当箇所を特定（例：盾耐久度パラメータ）
  ↓
EnemyShield.cs を修正
  ↓
Unity コンパイル確認
  ↓
該当ステップ のみ再テスト実行
  （例：ステップ 3「耐久度検証」だけ再実行）
  ↓
✓ OK なら次ステップへ
  要調整 が再度検出 → 修正再度実施
  ✗ NG → 原因深掘り
```

---

## 【問題 5】デバッグビジュアライズの具体的な手段がない
**Issue:** "盾が有効と判定される" という確認方法がビジュアルに頼っているが、デバッグ表示の実装方法が指定されていない

**具体的な問題:**
- Debug.DrawRay() で盾判定範囲を描画しているのか？
- インスペクタの盾HP表示があるのか？
- 記録する「スクリーンショット」は何を撮るのか不明確

**修正案:**
```
【テスト実行時のデバッグ表示】

必須：EnemyShield.cs に以下を実装（テスト中のみ）
- OnDrawGizmos() で盾判定範囲を Gizmo で描画
- Inspector に [SerializeField] ShieldHP を表示
- プレイ中に Console に "Shield hit" ログ出力

記録方法：
- ステップ3の盾破壊テスト時にスクリーンショット撮影
  （盾の色が破壊時に変わるタイミングを記録）
```

---

## 【問題 6】依存ファイルの現在実装状態が未把握
**Issue:** Phase 3 は実装完了を前提としているが、実装の完成度（スタブ実装なのか完成実装か）が不明

**具体的な問題:**
- EnemyShield.cs は「盾判定ロジック完全実装」か、それとも「ダメージ処理だけ」か？
- PlayerCollision.cs の盾判定ロジック統合状況は？

**修正案:**
```
【Phase 3 実行前にコード確認表を作成】

ファイル | 実装項目 | 状態 | 備考
EnemyShield.cs | 盾判定（Collider 判定） | 実装/未実装 | 
EnemyShield.cs | 耐久度トラッキング | 実装/未実装 | 
EnemyShield.cs | 破壊時エフェクト | 実装/未実装 | 
PlayerCollision.cs | 盾との衝突判定 | 統合/未統合 | 

例：EnemyShield.cs のダメージ処理に盾判定が含まれているか
→ `if (shieldActive) { shieldHP--; return; }` のコードがあるか確認
```

## 【問題 7】テスト実施言語・環境が曖昧
**Issue:** テスト実行手順は「Unity エディタで Play ボタン」と一般的だが、デバッグ言語の指定がない

**具体的な問題:**
- コンソールの出力が日本語か英語か不明確
- エラー発生時のトラブルシューティングが日本語なのか英語か？

**修正案:**
```
【推奨：テスト環境の統一】

- Unity Console の言語設定：日本語（既存コーベースに合わせる）
- Debug.Log() 出力：日本語でログ出力（例："盾ダメージ: 2/3"）
- エラー時の対応：
  - コンパイルエラー → Assets/Script/ のエラー位置を Unity UI で確認
  - ランタイムエラー → Console の Exception スタックトレースで原因特定
```
